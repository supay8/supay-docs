# Paquetes y masiva

Lotes para contingencia y alto volumen. Firman offline (`codigoEmision=2`) y
reservan numeración antes de enviar. `SENT` **solo** existe en flujo de lote (la
emisión individual nunca lo produce).

**En esta página aprenderás:** enviar paquetes de contingencia y emisión masiva, validar lotes y leer sus estados · **Prerrequisitos:** facturas `OFFLINE` o sector 30 · **Tiempo:** ~10 min.

## Paquete (contingencia)

| Campo | Tipo | Obligatorio | Descripción |
|---|---|---|---|
| `invoiceIds` | uuid[] | No | Ausente = auto (facturas `OFFLINE` pendientes). `null`, duplicados o string → `400` |

Validar antes de enviar: `POST /siat/packages/{batchId}/validate {}`.

## Masiva

Única vía del sector 30 (boleto aéreo): `sector:"30"` en individual → `400`.
El 30 admite borrador sin `items` (con `total` + pasajero y cabecera).

    ```typescript
    });

    // Validar el lote masivo (batchId sale del envío)

    ```

## Estados del lote

| Transición | Significado |
|---|---|
| `SENDING → SENT` | Lote reservado con `CodigoRecepcion` del SIAT |
| `SENT → ACCEPTED / OBSERVED / REJECTED` | Resultado por factura del lote |
| `OFFLINE → SENT` | Factura offline incorporada a un paquete aceptado |

<Callout intent="info">
  El XML de cada factura usa el mismo pipeline de la emisión individual. La firma
  se recalcula sobre el XML del lote: el hash difiere por definición; lo que se
  concilia es el contenido, no el hash.
</Callout>
