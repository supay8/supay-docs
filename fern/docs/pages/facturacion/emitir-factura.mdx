# Emitir factura

`POST /v1/invoices/emit` valida, crea y emite una factura en una llamada.
Necesitas una API key y un POS configurado con CUIS y CUFD.

```typescript
const invoice = await supay.invoices.emit({
  posId: pos.id,
  customer: {
    documentType: "ci",
    documentNumber: "1234567",
    name: "Ada Lovelace",
    email: "ada@example.com",
  },
  items: [{
    sku: "PLAN-PRO",
    description: "Plan profesional",
    codigoActividad: "101010",
    codigoProductoSin: 5113100,
    unidadMedida: 58,
    quantity: 1,
    price: 150,
  }],
});
```

Para listar, usa `supay.invoices.list({ posId: pos.id })`. Consulta una factura
por su ID y descarga sus comprobantes desde `/v1/invoices/{id}/xml` y
`/v1/invoices/{id}/pdf`.

Cada llamada de emisión crea una factura nueva. Si el resultado es incierto,
consulta la factura existente y su estado SIAT antes de repetir la emisión.
`OFFLINE` indica contingencia: conserva el ID y concilia por paquetes.

Los errores incluyen `error.code`, `error.message` y, cuando se identifica,
`error.field`. Corrige el payload indicado. Los campos desconocidos se rechazan.
No se necesita una llamada de preview ni un borrador previo.

## Opciones

`invoiceType` usa `sale` por defecto y `sector` usa `auto`. Para sectores
especializados, envía `data` e `items[].data` con los nombres fiscales del perfil.
Consulta los perfiles en `GET /v1/invoices/sectors`.

Para pagos, `payment` contiene `methodCode`, `currencyCode` y `exchangeRate`.
En ajustes, `referenceInvoiceId` identifica la factura original; el sector 24
requiere `layout`. El cliente se envía como snapshot: no incluyas `customer.id`.

El sector 30 usa la operación masiva `/v1/siat/bulk/{posId}`.
