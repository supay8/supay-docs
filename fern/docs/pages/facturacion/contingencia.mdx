# Contingencia OFFLINE

`emit` es síncrono: si el SIAT no responde por timeout/caída, la API **no falla**:
devuelve `200` con `status: "OFFLINE"`, XML firmado local (`codigoEmision=2`) y
`contingencyEventId`, vinculado a un evento significativo local.

**En esta página aprenderás:** qué pasa cuando cae la red SIAT, registrar el evento y reenviar por paquete · **Prerrequisitos:** saber [emitir](../facturacion/emitir-factura.mdx) · **Tiempo:** ~10 min.

<Callout intent="warning">
  Un rechazo (`REJECTED`) se informa de inmediato y **no** abre contingencia. Solo
  timeout/caída de red genera factura offline.
</Callout>

## Evento significativo

| Campo | Tipo | Obligatorio | Descripción |
|---|---|---|---|
| `codigo_motivo_evento` | int | No, default corte de internet | Motivo SIAT del evento |
| `descripcion` | string | No, default `"Corte del servicio de internet"` | Descripción |
| `cufd_evento` | string | No, default CUFD vigente | CUFD del evento |
| `fecha_hora_inicio_evento` | fecha | No | Default `now-10m` (clamp a vigencia CUFD) |
| `fecha_hora_fin_evento` | fecha | No | Default `now+1h50m` (se completa al volver la red) |

Requiere CUIS activo + CUFD vigente o responde `409`.

    // Registrar el evento significativo (usa defaults si omites campos)

      descripcion: "Corte del servicio de internet",
    });
    // ev.codigo_recepcion

    // Al volver la red: enviar por paquete y conciliar
    await supay.siat.sendPackage({

    });
    // OFFLINE → SENT → ACCEPTED / OBSERVED / REJECTED

        \"invoiceIds\": [\"$ID\"]

## Reglas operativas

| Regla | Detalle |
|---|---|
| Renovación | CUFD/CUIS se renuevan automáticamente; antes de emitir se valida CUFD vigente |
| Beta | `REJECTED` no se reencola — corregir y crear factura nueva, conservando ID/CUF |
